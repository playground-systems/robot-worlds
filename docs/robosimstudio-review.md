# RoboSimStudio engineering review

Reviewed 2026-11-02 at [`d474a18b`](https://github.com/robosimstudio/robosimstudio/tree/d474a18b0b70c8f8fae3bbd8ce43a8456e57969b). Source inspection only: no installation, execution, GPU job, import, or scene-authoring decision. RoboSimStudio is an interactive reconstruction toolkit; its live reconstructed `twins/` folders are explicitly uncommitted, so the repository is not itself a catalog of those reconstructed rooms. [Live workflow](https://github.com/robosimstudio/robosimstudio/blob/d474a18b0b70c8f8fae3bbd8ce43a8456e57969b/examples/live/README.md#L10-L27)

## Most useful pattern: load visuals once, stream body poses

There **is a decoupled browser mesh/material path**, but it reads Newton's model rather than exporting a native MuJoCo `MjModel` directly. It is a useful architectural reference for retaining our original source visuals alongside native physics:

| Source code | Concrete behavior and adaptation boundary |
| --- | --- |
| [`VisualPart`, `model_visual_parts`](https://github.com/robosimstudio/robosimstudio/blob/d474a18b0b70c8f8fae3bbd8ce43a8456e57969b/robosimstudio/core/render/visual.py#L47-L71) | A visual has a mesh, stable body index, and body-local matrix; its world matrix is `body_world @ visual_local`. The gather reads Newton `shape_source`, `shape_body`, `shape_transform`, visibility and scale. It does not recover visuals before the source model is compiled. |
| [`ViewerStudio._log_pbr_instances`](https://github.com/robosimstudio/robosimstudio/blob/d474a18b0b70c8f8fae3bbd8ce43a8456e57969b/robosimstudio_studio/garments.py#L952-L1045) | Send prototype geometry/material as `add_batched_glb` once; subsequent frames update position, quaternion and scale arrays. Batch by geometry and material. Static batches skip unchanged messages. This avoids resending texture/mesh bytes every physics step. |
| [`finish_gltf.glb_for`](https://github.com/robosimstudio/robosimstudio/blob/d474a18b0b70c8f8fae3bbd8ce43a8456e57969b/robosimstudio_studio/finish_gltf.py#L147-L198) | Cache encoded prototypes by geometry/material identity; clear when the model changes. | [`Viewer.show`](https://github.com/robosimstudio/robosimstudio/blob/d474a18b0b70c8f8fae3bbd8ce43a8456e57969b/robosimstudio/sim/draw.py#L183-L194) | Synchronize the device, then `begin_frame`, `log_state`, `end_frame`. Viewer lifecycle and simulation stepping are separate. |
| [`RendererGL`](https://github.com/robosimstudio/robosimstudio/blob/d474a18b0b70c8f8fae3bbd8ce43a8456e57969b/robosimstudio/solvers/render/gl.py#L1-L35) | A second, render-only MuJoCo model places visible mesh geoms on mocap bodies and updates them from physics body poses. It runs kinematics, not physics, and never alters the stepped model. This is an offscreen rasterizer, distinct from the browser transport above. |

**Engineering inference for our immediate texture-compilation problem:** keep original source GLBs/images available to our existing Three browser loader, with a checked mapping from each source visual to its native body and local transform. Publish an immutable visual manifest once and send native body poses thereafter. Keep joints, masses, contacts and state authoritative in native physics. This separation does not require putting high-resolution browser textures inside the native physics kernel. RoboSimStudio supplies the transport/frame pattern, **not** a ready-made precompile MuJoCo visual extractor or our required source-to-native mapping.

Do not copy its material conversion as a fidelity guarantee. Its browser helper reconstructs GLBs rather than passing the original source GLB through; no normal-map assignment appears in that encoder. The generic visual gather constructs materials with metallic `0` and roughness `0.7`. Browser PBR failures also fall back to a flat material. Retaining our original PBR maps and reporting a missing map explicitly is preferable for this project's source-preservation contract. [Encoder](https://github.com/robosimstudio/robosimstudio/blob/d474a18b0b70c8f8fae3bbd8ce43a8456e57969b/robosimstudio_studio/finish_gltf.py#L230-L266), [generic conversion](https://github.com/robosimstudio/robosimstudio/blob/d474a18b0b70c8f8fae3bbd8ce43a8456e57969b/robosimstudio/core/render/visual.py#L428-L448), [flat fallback](https://github.com/robosimstudio/robosimstudio/blob/d474a18b0b70c8f8fae3bbd8ce43a8456e57969b/robosimstudio_studio/garments.py#L952-L961)

## Import mechanisms without confusing them with appearance

- [`load_asset`](https://github.com/robosimstudio/robosimstudio/blob/d474a18b0b70c8f8fae3bbd8ce43a8456e57969b/robosimstudio/scene/assets.py#L105-L220) distinguishes the visual mesh from collision-only proxy meshes, disables collision on the visual when proxies exist, hides the proxies, and preserves body inertia while adding them. It refuses an approximation combined with authored proxies. Mesh imports do not stand in for MJCF/USD bodies and joints.
- [`add_usd_stage`](https://github.com/robosimstudio/robosimstudio/blob/d474a18b0b70c8f8fae3bbd8ce43a8456e57969b/robosimstudio/scene/build/imports.py#L430-L545) chooses engine variants, preserves/remaps source body/joint maps after fixed-joint collapse, and has explicit handling for declared colliders hidden inside instances or attached to Xforms. It reports unsupported articulation trees/loops. These are documented conversion operations, not proof that every USD can be imported unchanged.
- [`open_session_stage`](https://github.com/robosimstudio/robosimstudio/blob/d474a18b0b70c8f8fae3bbd8ce43a8456e57969b/robosimstudio/scene/build/imports.py#L55-L88) puts USD fixes in a fresh anonymous session layer, refusing accidental root-layer mutation. Reusable provenance principle: preserve source bytes and record each derived fix.
- [`shape_meshes`](https://github.com/robosimstudio/robosimstudio/blob/d474a18b0b70c8f8fae3bbd8ce43a8456e57969b/robosimstudio/core/render/visual.py#L349-L380) queries visible and colliding shape sets separately: visible picking and physical grasp clearance need different geometry. A matching silhouette cannot establish a usable cavity or contact surface.

## Interactive repair and robot API

The live server watches the scene and bounded local Python helpers, hashes them, rebuilds after a save, and swaps the page after a successful build. Build failure preserves the old scene; failure while adopting an already-built replacement can instead show a labeled bare stand-in. UI callbacks queue work for the simulation thread. Our immutable world versions can use this feedback pattern without executing arbitrary authored Python. [Watcher/loader](https://github.com/robosimstudio/robosimstudio/blob/d474a18b0b70c8f8fae3bbd8ce43a8456e57969b/robosimstudio_real2sim_agent/scenefile.py#L115-L159), [reload](https://github.com/robosimstudio/robosimstudio/blob/d474a18b0b70c8f8fae3bbd8ce43a8456e57969b/robosimstudio_real2sim_agent/server.py#L328-L432)

`snapshot`/`compare` produce a reference/render pair and object look sheet; recorded takes produce a timeline strip. The numeric `check` measures build success, finite state, camera aspect, named-object presence, initial penetration and short rest drift. Defaults are 60 steps, 1 mm penetration and 2 mm drift; unavailable object checks can be SKIP, and the command blocks nothing. It resets afterward. This is a reset sanity check, not visual approval, task completion, grasp evidence or a contact-only policy audit. The agent instructions separately require contact-only motion and disclosure of scripted shortcuts; those instructions are not enforced by this gate. [Comparison/gate contract](https://github.com/robosimstudio/robosimstudio/blob/d474a18b0b70c8f8fae3bbd8ce43a8456e57969b/examples/live/REFERENCE.md#L210-L278), [implemented gate](https://github.com/robosimstudio/robosimstudio/blob/d474a18b0b70c8f8fae3bbd8ce43a8456e57969b/robosimstudio_real2sim_agent/checks.py#L806-L940), [author instructions](https://github.com/robosimstudio/robosimstudio/blob/d474a18b0b70c8f8fae3bbd8ce43a8456e57969b/examples/live/AGENTS.md#L118-L150)

Robot interfaces separate `robot.*` motion/gripper/observation tools, `motion.*` planners, and privileged `sim.*` object-pose/grasp/success queries. `privileged=False` removes `sim.*`. Graph nodes support tool calls, script nodes and conditional retry branches; a scripted successful rollout is not an independently learned policy. A custom robot declares its MJCF, joint names, wrist and tool/gripper metadata. The docs require arm and rigid objects in the same MuJoCo engine for frictional pinch grasping. [Policy tools](https://github.com/robosimstudio/robosimstudio/blob/d474a18b0b70c8f8fae3bbd8ce43a8456e57969b/examples/07_policies/README.md#L91-L119), [robot declaration](https://github.com/robosimstudio/robosimstudio/blob/d474a18b0b70c8f8fae3bbd8ce43a8456e57969b/examples/04_extending/00_add_a_robot.py#L18-L44), [grasp caveat](https://github.com/robosimstudio/robosimstudio/blob/d474a18b0b70c8f8fae3bbd8ce43a8456e57969b/examples/05_studio/README.md#L85-L93)

## CPU/Mac and licensing limits

- Official tested platform: Linux x86-64, Python 3.12; **macOS and Windows are explicitly untested**. CPU mode steps arms/rigid bodies with MuJoCo C and some deformables with SuperDex; one world/process, no SDF/hydroelastic contact. SuperDex has no ARM64 wheel. Several material kinds refuse CPU execution. This is not a supported Mac replacement for our existing native MuJoCo path. [Installation/platform matrix](https://github.com/robosimstudio/robosimstudio/blob/d474a18b0b70c8f8fae3bbd8ce43a8456e57969b/examples/install.md), [Linux CPU CI](https://github.com/robosimstudio/robosimstudio/blob/d474a18b0b70c8f8fae3bbd8ce43a8456e57969b/.github/workflows/tests.yml)
- RTX appearance requires OVRTX plus supported NVIDIA RT hardware; CPU auto-rendering falls back to collider-only `tiled`. `gl` exists but is explicit-only, targets EGL/OSMesa, and refuses particle/deformable scenes. No native macOS CGL path was found in that renderer. The browser mesh path itself is distinct from these offscreen backends. [Renderer selection](https://github.com/robosimstudio/robosimstudio/blob/d474a18b0b70c8f8fae3bbd8ce43a8456e57969b/robosimstudio/solvers/render/__init__.py#L48-L71), [GL implementation](https://github.com/robosimstudio/robosimstudio/blob/d474a18b0b70c8f8fae3bbd8ce43a8456e57969b/robosimstudio/solvers/render/gl.py#L74-L87)
